# B16继电器与陶瓷发热片协同加热、阶梯温度采样

本版本基于小组仓库 `src_ads1263_pt1000_pid_vofa_3dp_calibrated`，使用 Smart ZYNQ SL V1.3B / XC7Z020CLG484-1、50MHz时钟、ADS1263的5 SPS驱动和PT1000模拟模块换算。基线保留仓库的温度修正参数 `TEMP_OFFSET_MDEG=1997`，实际探头应继续用参考温度计核对。

实物配置为220V、300W加热棒通过继电器供电，陶瓷发热片由H桥驱动。两路均用于加热。原PID符号约定继续使用：负U表示陶瓷片加热，正PID需求会停止陶瓷片加热并让系统自然降温。

## 文件与工程

`rtl`包含8个Verilog文件，`constraints`包含1个XDC。顶层为 `smart_zynq_ads1263_tec_pid`。新增文件 `heater_relay_window.v` 实现机械继电器慢周期控制。

用Vivado打开 `scripts/create_project.tcl` 建工程，或运行 `scripts/build.tcl` 完成综合、布局布线及bitstream生成。Vivado 2018.3请在纯英文目录使用，例如把本目录复制为 `E:/water_relay_experiment`。不要混入旧目录的同名顶层、控制器或XDC。

```tcl
cd E:/water_relay_experiment
source scripts/create_project.tcl
```

构建后的文件为 `output/relay_step_experiment.bit`。需要把本版本bitstream下载到FPGA，脚本才能使用新增的启停和心跳命令。

## B16与负载

| 连接 | 接法 |
|---|---|
| FPGA继电器控制输出 | BANK35排针丝印B16，顶层端口 `heater_relay` |
| B16 | 接继电器IN，按3.3V逻辑兼容要求连接 |
| 继电器DC− | 与FPGA信号GND共地 |
| 继电器DC＋ | 按实物SRD-03VDC模块的3V版本要求供电，确认模块供电范围 |
| 触发跳帽 | H与中间COM短接，高电平吸合 |
| 负载端 | 用COM与NO控制加热棒供电，NC悬空 |
| H桥 | 原接线：H19 RPWM、H20 LPWM、E18 R_EN、F18 L_EN |

模块供电需要独立的足够电流，GPIO只接IN。建议IN对低压GND加10kΩ外部下拉。上电、复位、停止、故障及失联都会关闭B16输出。

220V/300W加热棒额定电流约1.36A。市电接线应由熟悉市电的人完成，使用合适的绝缘外壳、接地、漏电保护和过温/防干烧保护。未完成这些条件前可只测试继电器触点通断。陶瓷片商品图片的“3.7–220V”列出了多种商品规格，H桥功率电源必须匹配你们实际购买的陶瓷片额定直流电压，不能据此把220V市电接进BTN7960。

## 控制行为

- 默认上电停止，等待连续3个有效测温样本。输入 `RUN` 后才允许加热。
- 原PID参数Kp/Ki/Kd(Q8)=2560/13/512，周期500ms，陶瓷片PWM为1kHz，默认最大80%。保留原斜率和20ms换向等待，输出仅使用加热方向。
- 两路加热共同使用负PID需求的绝对值。陶瓷片按该需求输出PWM；机械继电器按20秒窗口、1秒步长实现慢周期占空比，因此继电器占空比分辨率为5%，向下量化。
- 例如加热需求32.7%，陶瓷片PWM最终为32.7%，继电器窗口为30%，每20秒吸合6秒。新继电器比例在下一窗口边界应用。首次出现非零需求立即开始第一个窗口。
- STOP、设定值变化、复位、传感器异常和通信失联可以提前结束窗口，因而保护动作可能产生短于1秒的脉冲。正常完整窗口按1秒步长通断。
- PID停止时清积分。修改设定值时重置PID历史并重开继电器窗口。
- 测温有效窗口沿用−20～80°C，ADC异常、AO异常、样本超时锁存故障。连续3秒无有效心跳会关闭两路并锁存F=5。排查后按KEY1复位，再重新启动。
- 这些PID参数来源于原工程，新增300W加热棒后须在实物上重新整定。实际稳态波动、超调及所需稳定时间需要实验验证。

只有加热能力时，达到低于初始水温/环境可达温度的目标依赖自然散热。例如室温为25°C时，20°C阶段可能始终无法满足条件；脚本会等待并在超时后停机，不会把未达标数据记为稳态结果。

## 串口协议

板载PL USB-UART，115200、8N1、无流控。命令使用ASCII并以LF结束。

| 发送文本 | 动作 |
|---|---|
| `20.000`、`30`等 | 设定目标，保持原10～80°C限幅及最多3位小数格式 |
| `RUN` | 在测温正常且无故障时启动 |
| `STOP` | 停止两路并清除启动状态 |
| `PING` | 更新心跳，不会自行启动 |

例如脚本实际发送 `30.000\n`、`RUN\n`。有效RUN也会刷新心跳。脚本每500ms自动发送PING，最近1.5秒没有新遥测时停止发心跳。

回传示例为

```text
T=+0030.012C,SP=+0030.000C,U=-025.0%,S=R,F=0,H=020.0%,R=1,E=1,Q=00042
```

| 字段 | 含义 |
|---|---|
| T、SP | 当前温度、FPGA接受的目标，°C |
| U | 陶瓷片实际PWM，有符号百分比，负值表示加热 |
| S | W等待测温、D就绪但停止、R运行、F故障 |
| F | 0正常、1样本超时、2温度超窗、3 ADC、4 AO/电阻无效、5电脑心跳超时 |
| H | 当前完整继电器窗口采用的占空比，百分比 |
| R | 此刻B16逻辑输出，1吸合、0释放 |
| E | 启动状态，1启动、0停止 |
| Q | 报告序号，0～65535循环 |

R是FPGA发出的逻辑状态，继电器触点是否实际闭合仍需实物验证。H是慢周期比例，R会在窗口内变化。陶瓷片和加热棒功率不同，U与H不能直接相加作为总功率。

本版本沿用仓库的键值文本回传，电脑脚本负责解析。手工使用VOFA时按文本接收、ASCII发送命令。它与早期 `water:...` FireWater格式不同，旧版采样软件需使用本目录脚本替换。

## 阶梯采样脚本

电脑安装Python 3.9及以上、pyserial。关闭占用同一COM口的VOFA或其他串口软件。

```powershell
cd E:/water_relay_experiment/pc
python -m pip install -r requirements.txt
python step_experiment.py --port COM7
```

把COM7改为板上PL串口。可先用 `python -m serial.tools.list_ports` 查看端口。

用户确认的默认实验参数为

| 参数 | 默认值 |
|---|---|
| 温度阶梯 | 20、30、40、50、60、70°C |
| 稳定等待 | 连续120秒满足条件 |
| 温差带 | 全部样本在目标±0.3°C以内 |
| 漂移上限 | 最近120秒线性斜率绝对值≤0.1°C/分钟 |
| 占空比采集 | 稳定后继续采集60秒 |
| 单温度阶段超时 | 1800秒，含等待与采样 |

每级会先确认板上SP，再确认RUN。采样期间若温度超出稳定条件、丢失报告或序号中断，会丢弃本次部分统计并重新等待稳定。任何故障、失联或设定值被其他来源改变都会中止实验。阶段超时会停机，不跳过失败阶段。

每级完成后自动升到下一级。结束、Ctrl+C或异常时，脚本发送STOP并等待板上E=0、U=0、H=0、R=0确认，然后关闭串口。若拔线导致无法确认，固件依靠3秒心跳看门狗关闭输出。

修改参数的示例为

```powershell
python step_experiment.py --port COM7 --targets 20,30,40,50,60,70 --stable-seconds 120 --sample-seconds 60 --tolerance 0.3 --max-slope-c-per-minute 0.1 --stage-timeout 1800
```

脚本允许10～75°C递增目标，保留距离固件80°C保护阈值的余量。

结果自动保存在 `pc/logs/运行时间/` 下。

- `raw.csv` 保存等待和采样期间的T、SP、U、H、R、E、状态、故障和序号。被取消的采样尝试仍可在原始记录中追溯。
- `summary.csv` 每个成功温度点一行，包含样本数、时长、温度均值/标准差/最小/最大值、陶瓷片PWM百分比均值、继电器窗口百分比均值，以及根据R和接收时间积分估计的继电器实际ON比例。

summary中的陶瓷片占空比已转换为正百分比便于比较。根据R估计的ON比例受500ms报告周期及通信延迟影响；它是逻辑输出采样估计值。

## 无硬件验证

```powershell
python pc/step_experiment.py --demo --stable-seconds 0.3 --sample-seconds 0.3 --max-slope-c-per-minute 0.5 --stage-timeout 15
python -m unittest discover -s pc -p test_step_experiment.py -v
powershell -File scripts/run_sim.ps1
```

demo使用合成数据验证完整流程，日志目录带DEMO。它不代表加热装置实测性能，合成板只实现流程需要的简化温度响应。

HDL系统仿真在ADC驱动结果接口注入样本，验证真实温度换算、串口命令、PID、继电器/H桥及故障关断。既有ADS1263 SPI驱动和模拟输入电路的实物有效性仍需上板复核。
